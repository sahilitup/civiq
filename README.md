# CIVIQ: Gurugram garbage map

Photograph a garbage spot in Gurugram and pin it to a public map, tagged to its ward, councillor, zone officers, MLA and MP. It stays open until someone standing at the spot photographs it clean and a reviewer approves the photo. Modelled on NammaKasa (Bengaluru); the feature-by-feature comparison is in [FEATURES.md](FEATURES.md).

## Run it

Requires Node 22.13+ (uses the built-in `node:sqlite`). No `npm install` needed: the app has no dependencies.

```bash
npm start                       # real database: data/kachra.db, http://localhost:5173
npm run seed                    # DEMO ONLY: fills data/demo.db with fake reports
DB_PATH=data/demo.db npm start  # browse the demo
```

Camera and GPS need HTTPS on phones. Deploy behind HTTPS (the `Dockerfile` and `render.yaml` are ready for Render). Keep `data/` and `uploads/` on a persistent disk.

## Passcodes

On first run the server creates `data/secrets.local.json` (git-ignored) with random passcodes:

- `adminPasscode` opens the review console at `/admin` (approve cleanups, "not garbage" disputes and community listings)
- `dataPasscode` unlocks bulk downloads at `/downloads`

On a hosted server set `ADMIN_PASSCODE`, `DATA_PASSCODE` and `TOKEN_SECRET` as environment variables instead.

## Settings to fill in

`data/officials.json`: `follow` (your X, Instagram and Telegram handles; the Follow menu stays hidden until one is set) and `contact_email` (shown on `/contact`).

## Pages

| Path | What |
|---|---|
| `/` | Map, search, filters, nearby reports, report button |
| `/report/:id` | A report: photo, who must clean it, what to do now, share, verify cleanup, not garbage |
| `/ward/:n`, `/mla/:seat`, `/mp/gurgaon`, `/zone/:n` | Area pages with reports, insights and representatives |
| `/wards` | Ward leaderboard |
| `/communities`, `/communities/register` | Volunteer communities |
| `/analytics`, `/methodology` | Public numbers and how they are counted |
| `/downloads` | CSV / GeoJSON (passcode) |
| `/admin` | Review console (passcode) |
| `/status` | System status |
| `/about`, `/contact`, `/privacy`, `/terms` | Info pages (generated by `tools/build-pages.cjs`) |

## Wards and who is responsible

| File | What it is | Source | Accuracy |
|---|---|---|---|
| `data/ward-people.json` | 36 councillors with emails, 6 zone officer teams, commissioner | [mcg.gov.in ward-wise contacts](https://www.mcg.gov.in/contact/ward-wise-contacts) and [office contacts](https://www.mcg.gov.in/contact/office-contacts), checked 18 Nov 2026 | Official. Sanitary inspector and engineer offices (I–VI) are matched to zones I–VI by number, which is an assumption. |
| `data/wards.geojson` | 36 ward shapes (2025) | Built by `tools/build-wards.mjs` | **Approximate edges.** MCG publishes which localities each ward contains, not a map. Old-ward shapes are reused where they match a new ward; elsewhere each spot goes to the ward of its nearest listed locality (OpenStreetMap). |
| `data/assembly.geojson` | Gurgaon, Badshahpur, Sohna, Pataudi seats | 2008 delimitation, LGD via [bharatlas](https://bharatlas.com/view/lgd_assembly), CC0 | Exact |

Rebuild the ward map after editing `tools/wards-2025-localities.json` or `tools/geocode-overrides.json`:

```bash
cd tools && npm install
node geocode-localities.mjs && node fill-missing.mjs && node build-wards.mjs
```

Restart the server afterwards; it re-tags existing reports. If MCG releases an official ward map, save it as `data/wards.geojson` (with `ward_no`, `name`, `zone`) and it replaces the approximate one.

Re-check names and numbers in `data/ward-people.json` and `data/officials.json` against mcg.gov.in every few months. Officers get transferred often.
